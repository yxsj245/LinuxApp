# LinuxApp 使用说明

## 运行

根目录的 `index.html` 是纯静态项目主页，包含项目介绍、“一键使用”命令清单和“已有应用”清单。前者位于脚本中的 `apps` 数组，后者位于 `modules` 数组（需与 `config/modules.list` 保持一致）。部署到静态服务时请保持页面与 `main.sh` 的相对路径不变。

网页中的“复制命令”会生成当前静态站点对应的一键运行命令。按钮会通过 DOM 属性保存完整命令，避免命令中的引号影响复制；在 HTTPS、HTTP 和本地文件环境下分别尝试现代剪贴板接口与兼容性降级方案。浏览器只负责复制命令，不会自动执行本机 Shell 命令。

在 Linux 终端执行：

```sh
./main.sh
```

主界面上方显示系统基础信息和模块状态，下方为数字功能区。数字键会立即触发，不需要按回车。已安装列表使用普通的 `|` 分隔文本，不显示表格表头，也不显示模块前置字母键。

菜单按键的响应规则：

- 数字键按下立即执行，不需要回车确认。
- 在菜单里按回车、空格或 Tab 只会刷新当前界面，不会提示“无效选择”，也不会停住不动。
- 出现在操作结果下方的“按任意键继续...”对回车、空格等任意按键都有效，按下后即返回上一层菜单。

如果界面长期停在某个提示上且按键没有反应，通常是当前终端不支持交互输入（例如通过管道或脚本调用）。此时请改用真正的交互式终端运行 `./main.sh`，或者直接调用模块脚本接口做自动化。

离线模式：

```sh
./main.sh -offline
```

离线模式启动前会检查 `config/modules.list` 中登记的全部脚本；任意脚本缺失时不会进入菜单。

非交互终端不会启动菜单。自动化场景可以直接调用已注册模块脚本；当前已登记 4 个语言模块（Java、Node.js、Go、Rust）和 1 个软件模块（DeepSeek Harness），自动化用法、源选择与版本管理见 `docs/语言模块使用说明.md` 与 `docs/DeepSeek Harness 软件模块使用说明.md`。

```sh
# 语言模块示例
sh modules/language/java/module.sh status
sh modules/language/nodejs/module.sh capabilities
LINUXAPP_LANG_SOURCE=mirror LINUXAPP_LANG_VERSION=20 sh modules/language/nodejs/module.sh install
```

## 在线加载与缓存

`config/source.sh` 中的 `LINUXAPP_BASE_URL` 用于统一远端基地址，默认值为 `https://linuxapp.xiaozhuhouses.asia/`，模块相对路径会自动拼接。部署者仍可通过环境变量覆盖该地址；需要单独地址时，在 `linuxapp_script_override_url` 的 `case` 分支返回完整 URL。

`config/modules.list` 使用四列格式：`类型|模块 ID|相对脚本路径|显示名称`。模块不再配置或依赖英文字母键；进入“应用管理”后，先选择软件模块或语言模块，再按界面显示的数字序号进入具体模块。演示软件和演示语言保存在 `docs/`，仅作为开发参考，不会出现在运行菜单中。语言模块的菜单项会按模块自报能力动态生成，软件模块的菜单项会按模块自报的当前状态动态生成，都不需要在清单里额外配置。

语言依赖联动由 `lib/dependency.sh` 提供，它不依赖 `lib/ui.sh` 与 `lib/lang.sh`，因此框架菜单与模块脚本都能直接调用；离线模式会一并检查该文件是否存在。

默认缓存 3600 秒，目录优先使用 `XDG_CACHE_HOME/linuxapp`，否则使用 `~/.cache/linuxapp`。可通过环境变量覆盖：

```sh
LINUXAPP_BASE_URL=https://linuxapp.xiaozhuhouses.asia/ \
LINUXAPP_CACHE_TTL=3600 \
./main.sh
```

有本地脚本时，远端连接建立超时（默认 10 秒）会显示警告并回退本地脚本；本地脚本不存在时会等待远端结果。下载使用临时文件并原子替换。

`loader_ensure_script` 既接受 `config/modules.list` 里的相对路径，也接受脚本绝对路径（本地仓库脚本或缓存脚本）。传入绝对路径时直接使用，不会再与仓库根目录拼接；脚本加载失败时会同时打印传入值与实际检查的路径，便于排查路径拼接问题。

## 模块接口

软件模块必须支持：`install`、`start`、`stop`、`update`、`uninstall`、`status`；可选支持 `requires` 与 `extras`：

- `requires`：输出空格分隔的依赖语言键（对应 `config/modules.list` 中 `language` 类型的模块 ID，例如 `nodejs`）。框架在进入软件模块菜单时会显示这些依赖语言的状态，并在执行「安装」「更新」「启动」之前调用 `lib/dependency.sh` 确保依赖已安装：缺少时提示并询问，确认后直接调用该语言模块的 `install` 动作。自动化用 `LINUXAPP_APP_AUTO_DEPS=1`（自动安装）或 `0`（只提示不安装）控制。
- `extras`：按模块**当前状态**输出附加菜单项，每行 `动作键|中文名`，动作键会原样传给模块脚本。框架每次渲染软件模块菜单都会调用一次，因此它必须只读、快速且不联网；与六个基础动作同名的条目会被忽略。这个机制用于「只在异常状态才出现」的动作，例如 DeepSeek Harness 的「回滚到上一版本」。**动作键与动作名里都不能出现空白字符**：框架内部的动作用空格分隔，名字里带空格会被拆成多个菜单项。
- 软件模块的动作项同样按数字编号动态生成，基础动作顺序保持为：安装、启动、停止、更新、卸载、查看状态，附加动作排在其后。

语言模块必须支持：`install`、`uninstall`、`status`；可选支持 `capabilities`、`versions`、`switch`、`update`、`repair`。框架在进入语言模块时会先调用 `capabilities`，按返回值（空格分隔的能力名）动态生成菜单项：声明 `switch` 会增加“切换版本”，声明 `update` 会增加“更新”，声明 `repair` 会增加“修复环境”（重建环境变量注入与命令入口）。框架会拒绝语言模块的启动和停止动作。

语言模块的卸载支持按版本选择：列出已安装版本后输入编号只卸载该版本，输入 `a` 卸载全部版本，输入 `0` 或回车取消；非交互环境用 `LINUXAPP_LANG_UNINSTALL_VERSION=<版本号|all>` 指定。卸载当前版本会自动切换到剩余版本中最新的一个。

语言模块的安装位置、源选择、版本切换、更新与按版本卸载说明见 [语言模块使用说明](语言模块使用说明.md)。

状态命令输出一行管道分隔内容，第四列可选，用于凭证等敏感信息：

```text
状态|信息或版本|说明|可选敏感字段
```

第四列默认显示明文：带 token 的访问地址如果被遮住，用户就没法直接打开界面。需要隐藏时加 `--hide-secrets`
（`--show-secrets` 保留为兼容写法，与默认行为一致）。该开关会导出给模块，模块内的同类显示也遵循它。
敏感值不会写入缓存日志，但**默认明文意味着不要把菜单输出重定向到共享日志或公开位置**。

## SSH 登录钩子

安装当前用户的登录钩子：

```sh
./main.sh --install-ssh-hook
```

移除钩子：

```sh
./main.sh --remove-ssh-hook
```

钩子写入用户级 `.profile`，只在交互式 SSH 会话中运行，不替换用户 Shell。重复安装不会追加重复片段。

信号行为：在 `main.sh` 菜单中按 `Ctrl+C` 会恢复终端并退出脚本，回到普通 SSH 终端；子脚本执行安装或卸载时按 `Ctrl+C` 只终止当前任务，主菜单显示中断提示并返回当前模块的上一级菜单。

## 开发约定

所有脚本以 POSIX `sh` 为目标，文件末尾记录精确到分钟的 `Last updated` 时间（UTC）。测试脚本只在临时目录中生成，局部测试和完整测试结束后统一删除。

POSIX `sh` 没有局部变量，函数内的赋值会直接改写同名全局变量，因此框架内每个函数的参数与临时变量都必须带函数前缀（如 `msv_`、`rma_`、`loader_`、`lifecycle_`）。新增函数时禁止使用与调用方同名的变量：一旦覆盖了调用方的脚本路径，就会在“执行完动作返回界面刷新状态”时把缓存脚本的绝对路径当成相对路径去拼接，表现为提示“远程脚本下载失败且本地不存在”或“离线模式缺少脚本”，并将模块状态显示为 `异常 | 脚本不可用`，而重新进入模块又能自行恢复。
