# 语言模块使用说明

本文件说明 LinuxApp 内置语言模块（Java、Node.js、Go、Rust）的安装、版本切换、更新与卸载方式；
多个版本可以共存，卸载时既可以选择删除某个版本，也可以一次卸载全部版本。

## 一、支持的语言与能力

| 语言 | 模块 ID | 安装 | 切换版本 | 更新 | 安装源 |
| --- | --- | --- | --- | --- | --- |
| Java（Eclipse Temurin JDK） | `java` | 支持 | 支持（多版本共存） | 支持（补丁升级 / 可选大版本升级） | 清华 TUNA Adoptium / Adoptium 官方 |
| Node.js | `nodejs` | 支持 | 支持（多版本共存） | 支持（补丁升级 / 可选大版本升级） | npmmirror、华为云 / nodejs.org |
| Go | `go` | 支持 | 不提供（安装或更新时设为当前） | 支持（升级到最新 stable） | 阿里云 / go.dev |
| Rust（rustup） | `rust` | 支持 | 不提供（交由 rustup 管理） | 支持（`rustup update`） | 清华 / 官方 static.rust-lang.org |

在 `main.sh` 菜单中，语言模块的动作项会按模块自报的能力动态生成：

- Java、Node.js：`安装 / 切换版本 / 更新 / 修复环境 / 卸载 / 查看状态`
- Go、Rust：`安装 / 更新 / 修复环境 / 卸载 / 查看状态`

「修复环境」不联网、不改变已安装版本，只重新生成 `env.sh`、重写各启动文件的标记块并重建
命令链接，用于修复“装好了但命令找不到”或注入内容被误删的情况。

「卸载」会先列出已安装版本，再让用户选择删除哪一个：输入编号卸载指定版本，输入 `a` 卸载
**全部**版本，输入 `0` 或直接回车取消（这里的 `0` 是模块脚本内部的取消键，与菜单里的 `b` 返回不是一回事）。
卸载当前正在使用的版本时，会自动把 `current` 指向剩余版本中最新的一个并刷新环境；非交互环境用
`LINUXAPP_LANG_UNINSTALL_VERSION=<版本号|all>` 指定。详见第五章节。

## 二、安装位置与目录结构

安装根目录按当前用户权限自动选择，可用 `LINUXAPP_LANG_ROOT` 覆盖：

- root 用户：`/opt/linuxapp/lang`
- 普通用户：`${XDG_DATA_HOME:-~/.local/share}/linuxapp/lang`

```text
$LINUXAPP_LANG_ROOT/
├── env.sh                  # 自动生成的环境变量脚本，请勿手工修改
├── java/<版本>/            # Temurin JDK 解包内容
├── java/current -> <版本>  # 当前生效版本
├── nodejs/<版本>/ + nodejs/current
├── go/<版本>/ + go/current
├── go/.goproxy             # 存在表示已启用国内 GOPROXY
├── rust/                   # RUSTUP_HOME
├── cargo/                  # CARGO_HOME（含 config.toml 国内源配置）
└── cache/                  # 版本索引缓存，断网时用于兜底与“可升级”提示
```

环境变量注入使用受控标记块，重复安装不会产生重复内容。为了让**新开的终端**也能立即使用
（交互式非登录 shell 不会读取 `/etc/profile.d`），注入会覆盖两类启动文件：

| 用户 | 登录 shell | 交互式非登录 shell（新开终端等） |
| --- | --- | --- |
| root | `/etc/profile.d/linuxapp-lang.sh` | `/etc/bash.bashrc`（不存在时用 `/etc/bashrc`） |
| 普通用户 | `~/.profile` | `~/.bashrc` |

系统安装了 zsh 时再补充 `/etc/zsh/zshrc` 或 `/etc/zshrc`（普通用户为 `~/.zshrc`）。

标记块内容只有一行：读取 `<安装根>/env.sh`。`env.sh` 会按当前已激活的版本导出
`JAVA_HOME`、`GOROOT`、`GOPATH`、`RUSTUP_HOME`、`CARGO_HOME` 以及对应的 `PATH` 前缀。
`PATH` 采用去重写法，反复登录或重复加载不会出现重复条目；`GOPATH` 在未显式设置时取
`$HOME/go`，并把 `$GOPATH/bin` 加入 `PATH`（`go install` 的命令可直接调用）。

除环境变量外，还会在命令目录中建立命令入口，使命令在**任何** shell 中都能直接调用，
包括不读取任何启动文件的场景（`ssh 主机 'go version'`、脚本、cron、面板控制台）：

- root：`/usr/local/bin`（系统默认 `PATH` 已包含）
- 普通用户：`~/.local/bin`

| 语言 | 命令入口 | 形式 |
| --- | --- | --- |
| Java | `java`、`javac`、`jar`、`javadoc`、`javap`、`jshell`、`keytool` | 符号链接 |
| Node.js | `node`、`npm`、`npx`、`corepack` | 符号链接 |
| Go | `go`、`gofmt` | 符号链接 |
| Rust | `rustup`、`cargo`、`rustc`、`rustdoc`、`rustfmt`、`cargo-clippy`、`clippy-driver` | 包装脚本 |

Java、Node.js、Go 使用符号链接，固定指向 `<安装根>/<语言>/current/bin`，因此**版本切换后自动
指向新版本**，无需重新登录或重新配置。

Rust 的命令是 rustup 代理，必须依赖 `RUSTUP_HOME`、`CARGO_HOME` 才能定位工具链，因此改为写入
同名包装脚本：脚本内部先导出这两个变量，再执行 `<安装根>/cargo/bin/` 下的真实程序。这样
`rustup`、`cargo`、`rustc` 在未加载环境变量的非交互 shell 中也能正常工作，切换默认工具链后
无需重建。包装脚本带有 `linuxapp-lang-wrapper` 标记，卸载时按标记精确删除。

若目标位置已有同名文件且不是本程序创建的链接或包装脚本，则跳过该命令并给出中文提示，
绝不覆盖；卸载时会自动清理由本程序建立的内容。

安装完成后：

- 新开的终端（含 SSH 重新登录、面板控制台）自动生效；
- 当前终端可执行 `. <安装根>/env.sh` 立即生效；
- 命令链接对当前终端也立即有效，可直接执行 `go version`、`node -v` 验证。

本模块不使用 `update-alternatives`，也不会覆盖系统自带的 java/node，避免影响系统包管理。

### 安装是幂等的

当 `current` 指向的版本确实可用（目录与可执行文件都在）时，再点「安装」不会重新走一遍
安装向导，而是直接提示已经安装，例如：

```text
[信息] Node.js 24.21.0 已安装且可用，无需重复安装。
如需升级请选择「更新」，如需切换到其它已安装版本请选择「切换版本」；
确实要重装同一版本时，请设置 LINUXAPP_LANG_FORCE_INSTALL=1 后重试。
```

这一点在“软件模块依赖联动”场景下尤其重要：软件模块的安装动作会调用对应语言模块的
`install`，如果语言模块每次都进入选择源、拉取版本列表、等待确认的向导，用户会以为“装过了
又重新装了一遍”，非交互（无终端）环境下还会因为拿不到输入直接失败。Rust 同样如此：工具链
已存在时「安装」直接返回，不再顺手联网执行 `rustup update`；需要升级请显式选择「更新」，
需要重装请设置 `LINUXAPP_LANG_FORCE_INSTALL=1`。

## 三、安装源：国内镜像与官方源

**每次安装和更新都会询问使用哪个源，选择结果不会写入任何记录。** 需要自动化调用时通过
`LINUXAPP_LANG_SOURCE=mirror|official` 指定。

| 语言 | 国内镜像 | 官方源 | 备注 |
| --- | --- | --- | --- |
| Java | `mirrors.tuna.tsinghua.edu.cn/Adoptium` | Adoptium API + GitHub Releases | 元数据固定走 Adoptium API；清华镜像通常只保留各 LTS 的**最新补丁**，安装旧补丁时会自动回退到官方源 |
| Node.js | `registry.npmmirror.com/-/binary/node`（备：华为云） | `nodejs.org/dist` | 索引与 `SHASUMS256.txt` 各源内容一致 |
| Go | `mirrors.aliyun.com/golang` | `go.dev/dl` | 国内源元数据使用 Go 官方中国站 |
| Rust | `mirrors.tuna.tsinghua.edu.cn/rustup`（备：中科大） | `static.rust-lang.org` | 清华镜像不提供 `rustup-init.sha256`，校验值固定从官方站点获取 |

下载失败时的行为：先提示并自动改用另一个源重试一次；两个源都失败才报错退出，且不留下临时文件。

版本号列表、下载地址、校验值全部来自上游接口**动态获取**，代码中没有写死具体版本。

## 四、切换版本与更新的区别

- **切换版本**（Java、Node.js）：只在**已安装**版本之间切换，立即生效、不联网，可随时回退。
  切换后会重写 `env.sh` 并提示当前终端如何立即生效。
- **更新**：联网检查最新版本 → 下载校验 → 安装 → 切换为当前版本，旧版本保留，可马上用
  “切换版本”回退。

更新的三种策略（环境变量 `LINUXAPP_LANG_UPDATE`）：

| 取值 | 行为 |
| --- | --- |
| `patch`（默认） | 升级到当前大版本的最新补丁；若已是最新，则询问是否升级到更新的 LTS 大版本（默认否） |
| `major` | 直接升级到比当前更新的最近 LTS 大版本（Java、Node.js） |
| `latest` | 直接升级到最新 LTS 大版本的最新补丁 |

Go 与 Rust 的“更新”分别等价于“安装最新 stable 并切换”“执行 `rustup update`”。
Go 与 Rust 没有“切换版本”（Rust 的工具链切换交由 rustup 管理）。

“查看状态”会显示当前版本、安装根目录、已安装版本列表；若本地缓存索引显示存在更新版本，
还会提示“可升级到 X（运行「更新」）”。该提示基于本地缓存，可能比上游略滞后，且状态查询**不联网**。

## 五、按版本卸载

安装与更新会保留历史版本（便于回退），因此卸载时可以选择要删除的版本：

```text
已安装的 Node.js 版本：
  1. 22.23.2（当前）
  2. 20.20.2
  a. 卸载全部版本
  0. 取消
请输入编号、a（全部）或 0（取消）：
```

| 输入 | 行为 |
| --- | --- |
| 版本编号 | 只删除该版本目录，其它版本与生态环境保持不变 |
| `a` | 卸载全部版本：删除整个安装目录，并清理该模块写入的生态源配置 |
| `0` 或直接回车 | 取消，不做任何改动 |
| 其它内容 | 中文提示后重新询问（连续 5 次无效则取消） |

行为细节：

- **卸载非当前版本**：`current` 不变，`env.sh`、启动文件标记块与命令入口保持原样；
  `~/.npmrc`、GOPROXY、cargo 源配置都会保留（仍有版本在使用）。
- **卸载当前版本**：自动把 `current` 指向剩余版本中最新的一个，并在结果中提示新的当前版本，
  无需手工重新激活或重新登录。
- **卸载最后一个版本**：等同于卸载全部——删除语言安装目录，并移除该模块写入的生态源标记块；
  当所有语言都卸载后，还会清理 `env.sh`、启动文件标记块与命令入口。
- 版本列表会忽略 `current` 链接与安装过程中的隐藏目录（例如 `.staging.<pid>` 残留），
  不会把临时目录当成版本。
- 卸载过程不联网，也不影响其它语言。
- Rust 以工具链（toolchain）为单位选择，名称如 `stable-x86_64-unknown-linux-gnu` 或
  `1.75.0-x86_64-unknown-linux-gnu`；卸载当前默认工具链且还有其它工具链时，会先把默认
  工具链切换到剩余中的一个（优先 `stable`）再卸载。

自动化（非交互）用法：

```sh
# 卸载指定版本
LINUXAPP_LANG_UNINSTALL_VERSION=20.20.2 LINUXAPP_LANG_YES=1 \
  sh modules/language/nodejs/module.sh uninstall

# 卸载全部版本
LINUXAPP_LANG_UNINSTALL_VERSION=all LINUXAPP_LANG_YES=1 \
  sh modules/language/java/module.sh uninstall
```

未设置该变量且没有控制终端时，模块会给出中文提示并要求指定变量，不会自行猜测。

## 六、生态源配置（可选）

选择国内镜像安装后，模块会询问是否同时配置国内生态源。**默认不配置**（直接回车为否），
自动化场景必须显式设置 `LINUXAPP_LANG_ECOSYSTEM_MIRROR=1` 才会写入。

| 语言 | 内容 | 写入位置 |
| --- | --- | --- |
| Node.js | `registry=https://registry.npmmirror.com` | `~/.npmrc` |
| Go | `GOPROXY=https://goproxy.cn,direct` | `<安装根>/go/.goproxy`（由 `env.sh` 导出） |
| Rust | crates.io 稀疏镜像 | `<安装根>/cargo/config.toml` |

写入规则：

- 修改前先备份为 `<文件>.linuxapp.bak`（已存在则不覆盖）；
- 内容用 `# >>> linuxapp ... >>>` / `# <<< linuxapp ... <<<` 标记包裹；
- 卸载时按标记精确移除，并提示备份文件位置；Go 与 Rust 的配置位于安装目录内，随目录一并删除。

## 七、命令行用法（自动化）

模块脚本可以直接调用，适合脚本化与 CI：

```sh
# 查看能力与状态
sh modules/language/java/module.sh capabilities
sh modules/language/java/module.sh status
sh modules/language/java/module.sh versions

# 安装（示例：国内源、JDK 17 最新补丁）
LINUXAPP_LANG_SOURCE=mirror LINUXAPP_LANG_VERSION=17 sh modules/language/java/module.sh install

# 切换版本（Java、Node.js）
sh modules/language/java/module.sh switch 17.0.20.1

# 更新（Node.js 升级到 22.x 最新补丁）
LINUXAPP_LANG_SOURCE=mirror LINUXAPP_LANG_UPDATE=patch sh modules/language/nodejs/module.sh update

# 修复环境（重建环境变量注入与命令链接，不联网）
sh modules/language/go/module.sh repair

# 卸载（指定版本号只卸载该版本，all 表示卸载全部版本）
LINUXAPP_LANG_UNINSTALL_VERSION=1.27.1 LINUXAPP_LANG_YES=1 sh modules/language/go/module.sh uninstall
LINUXAPP_LANG_UNINSTALL_VERSION=all LINUXAPP_LANG_YES=1 sh modules/language/go/module.sh uninstall
```

`status` 输出为 `状态|信息或版本|说明`，`versions` 每行输出 `版本|current` 或 `版本|installed`，
`capabilities` 输出空格分隔的能力名，便于脚本解析。

### 自动化环境变量

| 变量 | 说明 |
| --- | --- |
| `LINUXAPP_LANG_SOURCE` | `mirror` 或 `official`；非交互环境必须指定 |
| `LINUXAPP_LANG_VERSION` | 指定安装版本。Java 接受大版本（如 `17`）或完整版本（如 `17.0.18`）；Node.js 接受大版本或完整版本（可带 `v`）；Go 接受 `1.27.1` |
| `LINUXAPP_LANG_UPDATE` | `patch`（默认）、`major`、`latest` |
| `LINUXAPP_LANG_YES` | `1` 表示自动确认所有询问 |
| `LINUXAPP_LANG_UNINSTALL_VERSION` | 卸载动作指定的版本号；`all`（或 `a`）表示卸载全部版本。非交互环境必须指定 |
| `LINUXAPP_LANG_ECOSYSTEM_MIRROR` | `1` 写入国内生态源，`0` 不写入 |
| `LINUXAPP_LANG_FORCE_INSTALL` | `1` 表示即使当前版本已就绪也强制重走安装流程（默认 `0`，已就绪时「安装」直接返回） |
| `LINUXAPP_LANG_ROOT` | 覆盖安装根目录 |
| `LINUXAPP_LANG_PROFILE_FILE` | 覆盖环境变量注入目标文件（指定后只写该文件） |
| `LINUXAPP_LANG_BIN_DIR` | 覆盖命令链接目录（默认 root 为 `/usr/local/bin`，普通用户为 `~/.local/bin`） |
| `LINUXAPP_LANG_SKIP_CHECKSUM` | `1` 表示在完全取不到官方校验值时跳过校验（仅在 Rust 官方校验文件不可达时需要） |
| `LINUXAPP_LANG_RUST_PROFILE` | rustup 安装 profile，默认 `default`，可设为 `minimal` 减少下载量 |
| `LINUXAPP_LANG_RUST_TOOLCHAIN` | rustup 默认工具链，默认 `stable` |
| `LINUXAPP_LANG_CONNECT_TIMEOUT` | 网络连接超时秒数，默认 15 |

非交互环境（没有控制终端）下，缺少必需的源或版本参数时模块会**明确报错退出**，不会猜测默认值。

## 八、常见问题

**1. 下载校验失败，提示“文件可能被篡改或镜像不完整”**
安装会立即中止并删除下载文件。请重新执行；若持续失败，可换另一个源（重新安装时选择另一个选项）。

**2. 选择国内镜像后仍从官方源下载**
清华 Adoptium 镜像只保留各 LTS 的最新补丁，安装历史补丁时会自动回退官方源，属预期行为。
Node.js 与 Go 的国内镜像保留全部版本，不会出现该情况。

**3. 提示“系统中找不到 curl 或 wget”**
请先安装 `curl` 或 `wget`，并确保 `tar`、`sha256sum` 可用（Debian/Ubuntu 默认具备）。

**4. 提示“当前 CPU 架构不受支持”**
目前支持 x86_64 与 aarch64，其他架构请自行编译安装。

**5. 断网时状态查询为什么还能显示版本？**
`status`、`versions` 只读取本地目录与 `current` 链接，不联网。“可升级到 X”的提示来自
本地缓存索引，断网时仍然可用但可能滞后。

**6. 安装完成后新终端找不到命令**
按顺序排查：

1. `ls -l /usr/local/bin/go`（普通用户 `ls -l ~/.local/bin/go`）是否存在。存在则命令链接正常，
   `command -v go` 应指向该路径；
2. 执行 `. /opt/linuxapp/lang/env.sh`（普通用户为 `${XDG_DATA_HOME:-~/.local/share}/linuxapp/lang/env.sh`），
   若这样能找到命令，说明只是当前终端没加载启动文件，新开终端会自动生效；
3. 若出现“已存在同名命令 … 已跳过”的提示，说明该位置已有其他来源的同名文件，
   需自行处理后重新执行一次安装或切换（本程序不会覆盖他人文件）；
4. `env.sh` 与链接都指向 `current`，版本切换后无需改任何配置。

**7. 卸载会删除什么？**
卸载前会列出全部已安装版本，可以只删其中一个，也可以选 `a` 卸载全部：

- 只删某个版本时，仅删除该版本目录；若删的是当前版本，会自动把 `current` 指向剩余版本中最新
  的一个，其它版本、`env.sh`、命令入口与生态源配置都保持不变；
- 选 `a` 卸载全部版本（或删除最后一个版本）时：删除该语言的整个安装目录（含全部版本与
  `current` 链接）、由本模块建立的命令入口（只删除指向安装根目录的链接与本程序生成的包装
  脚本，其他文件不动）、由本模块写入的 npm / cargo 国内源标记块（若存在）；
- 当所有语言都卸载后，会一并清理 `env.sh`、全部启动文件中的标记块，并删除
  `/etc/profile.d/linuxapp-lang.sh`。

不会删除系统自带 java/node，也不会删除用户自己的 `~/.cargo`、`~/.rustup`（只会提示）。

**8. Rust 的 `rustc`、`cargo` 为什么不是符号链接？**
Rust 的命令是 rustup 代理，必须依赖 `RUSTUP_HOME`、`CARGO_HOME` 定位工具链，因此在
`/usr/local/bin`（普通用户 `~/.local/bin`）中写入的是同名包装脚本：脚本内部先导出这两个变量，
再执行 `<安装根>/cargo/bin/` 下的真实程序，保证在 `ssh 主机 'rustc --version'`、定时任务等
未加载环境变量的场景也能直接用。包装脚本带 `linuxapp-lang-wrapper` 标记，误删后执行一次
「修复环境」即可重建，卸载时按标记自动清理。

**9. 磁盘占用**
每个 JDK 约 200–350 MB，每个 Node.js 约 60–120 MB，Go 约 250 MB，Rust（`default` profile）
约 1 GB。多个版本会累加，可直接用「卸载」选择要删除的旧版本，程序会自动刷新 `env.sh`
与命令入口，不需要手工删目录。
